# F-16C NAV and Landing HUD Design

## Scope

Build a cockpit-only F-16C HUD runtime from `FlightSim.Platform.Contracts.HudState`. The runtime creates its own uGUI hierarchy and has no scene, prefab, input, physics, or `Camera.main` dependency.

## Integration API

`F16HudController` is the sole integration component. The owning cockpit system calls `SetCockpitContext(bool, Camera)` when cockpit visibility or camera changes and `SetHudState(HudState)` when a new presentation snapshot arrives. The controller disables its complete generated hierarchy unless cockpit mode is active, a usable explicit camera exists, the state is valid, and `HudState.Mode` is not `HudMode.Off`.

## Rendering Architecture

- A generated screen-space-camera `Canvas` uses `CanvasScaler.ScaleWithScreenSize`, a 1920x1080 reference resolution, and height matching for the supported landscape targets.
- A centered, aspect-preserving combiner root contains a `RectMask2D`, one reusable `HudVectorGraphic`, and pooled `TextMeshProUGUI` labels.
- `HudVectorGraphic` converts retained vector commands into quads with `VertexHelper`. It supports solid and dashed lines, circles, polylines, boxes, carets, diamonds, and crosses without textures or `OnGUI`.
- `HudLabelPool` pre-creates a bounded set of labels and reuses them each refresh. It does not instantiate labels during normal updates.
- `F16HudLayoutMath` owns validation, SI-to-cockpit display conversion, heading wrapping, safe-area calculation, angle projection, clipping, and roll transforms.
- `F16HudComposer` maps a valid state to vector commands and pooled labels in non-overlapping layout zones.

## Symbology

The NAV and Landing layouts follow the current Eagle Dynamics F-16C guide organization within the available contract surface: boresight cross, conformal FPM, roll-stabilized five-degree pitch ladder and horizon, airspeed and altitude tapes, heading tape, VVI, current G and Mach, radar altitude, steerpoint diamond and great-circle steering cue, steerpoint number/distance, master warning/caution, master-arm state, and selected store/quantity. Landing mode adds the AoA bracket and landing-gear indication.

The FPM and steerpoint diamond use angular coordinates from `HudState` and are constrained to the combiner with off-screen cue treatment. Pitch lines remain roll stabilized while their center follows lateral flight-path drift.

## Responsive Layout

The Canvas reference is 1920x1080. The combiner uses a fixed 760x640 design aspect and shrinks only when the available logical canvas is smaller, preserving margins on ultrawide and 4:3 displays. Height matching makes line width and text size scale with the minimum dimension for all specified landscape aspect ratios. Tape windows and fixed data zones prevent labels from crossing the central flight references or each other.

## Validation and Failure Behavior

Every numeric field consumed by layout must be finite. Invalid values, invalid state, an off mode, inactive cockpit context, or a missing/disabled camera fully deactivate the generated HUD root. Strings are sanitized and truncated before display. No input polling, `Rigidbody` access, world-object lookup, or implicit camera lookup is permitted.

## Verification

EditMode tests cover state gating, supported aspect ratios, projection/clamping, heading wrapping, unit conversion, and command/label capacity. Compilation is checked through Unity batch mode when the installed editor can be located; otherwise generated project/compiler diagnostics are reported as a limitation.
