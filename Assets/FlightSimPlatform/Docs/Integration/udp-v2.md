# FlightSim UDP Protocol V2

## Transport

- Default telemetry source bind: `127.0.0.1:49000`.
- Default telemetry destination: `127.0.0.1:49001`.
- Datagram size is at most 1200 bytes. No fragmentation or retry is performed.
- Every integer and IEEE-754 double is little-endian.
- Booleans are one byte: `0=false`, nonzero is rejected by current decoders unless written by the codec.
- Variable strings are `uint16 byteLength` followed by UTF-8 bytes.
- Fixed aircraft IDs occupy 32 bytes: one-byte UTF-8 length, up to 31 data bytes, then zero padding.

## Header

All packets start with this 58-byte header:

| Offset | Bytes | Type | Field | Rule |
|---:|---:|---|---|---|
| 0 | 4 | `uint32` | Magic | bytes `46 53 49 4D` (`FSIM`) |
| 4 | 2 | `uint16` | ContractVersion | `2` |
| 6 | 2 | `uint16` | MessageType | table below |
| 8 | 4 | `uint32` | Sequence | monotonically increasing per sender |
| 12 | 8 | `uint64` | Tick | authoritative 100 Hz simulation tick |
| 20 | 32 | fixed UTF-8 | AircraftId | empty for mission-global packets |
| 52 | 2 | `uint16` | PayloadLength | datagram length minus 58 |
| 54 | 4 | `uint32` | CRC-32 | IEEE polynomial `0xEDB88320` |

CRC-32 is calculated over header bytes 0..53 and the payload, as if checksum bytes 54..57 were absent. Initial CRC is `0xFFFFFFFF` and the result is bitwise inverted.

## Message Types

| Value | Type | Domain | Payload source |
|---:|---|---|---|
| 1 | `FastState` | 50 Hz | `AircraftFastState` |
| 2 | `SystemsState` | 10 Hz | `AircraftSystemsState` |
| 3 | `TacticalPictureState` | 5 Hz | `TacticalPictureState` |
| 4 | `SimulationEvent` | immediate | `SimulationEvent` |
| 5 | Reserved | unsupported | no public encoder/decoder |
| 6 | Reserved | unsupported | no public encoder/decoder |
| 10 | `MissionState` | 5 Hz | `MissionState` |
| 11 | `MissionActorState` | 5 Hz per actor | `MissionActorState` |
| 12 | `MissionObjectiveState` | 5 Hz per objective | `MissionObjectiveState` |
| 13 | `AircraftCombatState` | 10 Hz per actor | `AircraftCombatState` |
| 14 | `AutomationRunState` | 5 Hz | `AutomationRunState` |
| 15 | `MissionEvent` | immediate | `MissionEvent` |
| 16 | `WeaponEngagementEvent` | immediate | `WeaponEngagementEvent` |

The exact payload order is the order written by `UdpPacketCodec`. Integration code in the same solution should call its `TryDecode*` methods rather than duplicate the layout. Field meaning and units are in [data-dictionary-v2.csv](data-dictionary-v2.csv).

## Receiver Rules

1. Reject datagrams shorter than 58 bytes or longer than 1200 bytes.
2. Verify magic, contract version, known message type and exact payload length.
3. Verify CRC before reading payload data.
4. Track `Sequence` independently of `Tick`; sequence detects transport loss and tick orders simulation state.
5. Partition aircraft state by the header `AircraftId`.
6. Treat UDP as a snapshot/event feed. Missing packets never block the simulator.
7. In v2 external applications are telemetry consumers only. The endpoint never receives datagrams and exposes no command parser; mission and pilot-control ownership remains in-process.

## Test Vectors

[udp-v2-test-vectors.json](udp-v2-test-vectors.json) contains complete datagrams generated by the current codec. A conforming decoder must accept each vector and reproduce its expected fields. Flipping any bit without recomputing CRC must make decoding fail.
